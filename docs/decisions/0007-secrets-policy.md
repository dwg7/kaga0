# 7. 公開リポジトリに秘匿情報を残さないための構成

- ステータス: 承認
- 日付: 2026-08-29

## 状況

`dwg7/kaga0` はPublicリポジトリである。一方でこのプロジェクトはハードウェア実機を
伴い、実際の運用には「実機のホスト名」「ログインユーザー名」「SSH鍵ファイル」等の
環境固有の値が必要になる。これらをMarkdownやシェルスクリプトに直接書いてしまうと、
- 個体名(コードネーム)を通じて手元の他のホスト管理慣習が推測できてしまう
- 将来、実際のIPアドレスやアカウント名を書いてしまうミスが起きやすくなる

一方で、「藤村さん自身が半年後に見返しても再現できる」「Claude Codeが次のセッションで
迷わず同じ手順を踏める」ためには、再現に必要な手順そのものは具体的に記録しておく必要がある。
**手順(How)は公開して問題ないが、実値(What/Which)は環境ごとに閉じておきたい** という
整理になる。

## 決定

1. **手順はMarkdown/スクリプトに書く。実値は `.env` に書く。**
   - `.env.example`(git管理下)には `KAGA_HOST=kaga0.local` のような一般的な
     プレースホルダーのみを書く
   - `.env`(git管理外、`.gitignore`に追加済み)に実際のホスト名・ユーザー名・
     鍵ファイルパスを書く
   - Justfileは `set dotenv-load` により `.env` を自動で読み込むため、
     レシピ自体には実値を埋め込まなくてよい
2. **平文パスワード・秘密鍵の内容はいかなるファイルにも書かない。**
   - `flash-sdcard.sh` はRPiアカウントのパスワードを対話プロンプトで受け取り、
     SDカードのbootパーティション上の `custom.toml` に書き込む(このファイルは
     SDカードの外に出ない。`.gitignore`にも `custom.toml` を追加済み)
   - SSH認証は公開鍵のみを使い、パスワード認証は無効化する
     (`password_authentication = false`)。パスワードはコンソールログイン用の
     フォールバックとしてのみ残す
3. **`.gitignore` で防御する。** `.env`、`custom.toml`、`id_ed25519*`等の
   秘密鍵っぽいファイル名、OSイメージ本体を除外する。

## 結果

- リポジトリを見た第三者は「どうやればいいか」を完全に再現できるが、
  「藤村さんの実機が具体的に何と呼ばれ、どのIPにいるか」は分からない
- 新しいセッション(Claude Code)がこのリポジトリで作業を始めるときは、
  `.env` が存在するかを確認し、なければ `.env.example` から作るよう促す
  (`just setup` が確認する)
