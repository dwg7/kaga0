# ネットワーク疎通トラブルシューティング

`$KAGA_HOST`(`.env`で設定した実機のmDNSホスト名)へのSSH接続ができない場合の切り分け手順。

## 前提知識

`.local`名前解決はmDNS(Avahi)に依存する。**省庁・自治体・防災機関ネットワークでは
mDNS(UDP 5353)がブロックされている可能性が高い**(kitavolcaのGitHub Pagesアクセス制限と
同根の問題 — [CLAUDE.md](../CLAUDE.md) 参照)。開発時の疎通確認と、実配備先での接続性検証は
別問題として扱うこと。

## 切り分け手順

### 1. IPアドレスでの疎通確認(mDNSを迂回)

```bash
# RPi Foundation割当MACアドレス(b8:27:eb, dc:a6:32, e4:5f:01 で始まるもの)をARPテーブルから探す
arp -a | grep -iE "b8:27:eb|dc:a6:32|e4:5f:01"
```

見つかったIPに直接SSHする:

```bash
ssh <ユーザー名>@<見つけたIP>
```

### 2. RPi側でAvahiの状態確認(SSHで入れた場合)

```bash
systemctl status avahi-daemon
hostname
```

### 3. ネットワークスキャンでの発見(ARPで見つからない場合)

```bash
# 手元のMacと同じサブネットをスキャン(例: 192.168.1.0/24)
nmap -sn 192.168.1.0/24
```

### 4. mDNSがブロックされている環境での運用

配備先ネットワークでmDNSが使えないと判明した場合の代替案:

- ルーター/DHCPサーバーで固定IPまたはDHCP予約を設定
- `/etc/hosts` に手元PCから直接IPを登録
- HDMI+キーボードで実機のコンソールから直接操作(SSH自体が不要になるケース)

いずれも現地ネットワークの管理者権限が必要になる可能性が高く、
**人間(藤村さん)側での切り分け** が必要な領域 — [CLAUDE.md セクション7](../CLAUDE.md#7-ハードウェアプロジェクトにおける作業分担重要) 参照。
